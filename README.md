# 车机 → 仪表屏投放研究（E28U / i.MX6 仪表）

在**自有车辆**上研究如何把自定义画面投到仪表屏上，并保留原车仪表元素（报警灯、指针、边框）。
仓库包含：方案评审、零写入探查工具、30510 管理通道客户端、最小投放验证、以及一个可独立运行的
Android APK（在车机本地完成全部流程，不依赖电脑）。

> ## ⚠️ 免责声明
>
> 本项目是**针对本人名下车辆的授权安全研究**，目的是评估第三方方案的技术可行性与风险，
> 并为车主自己可控的场景做最小验证。
>
> - 仪表屏是安全相关部件。**任何写入错误都可能让仪表黑屏或显示错误信息**，行驶中后果严重。
> - 仓库内工具会通过一个**无鉴权的管理端口**在仪表上执行 root 命令。**不要对非自有车辆使用**，
>   这属于未授权访问计算机信息系统。
> - 文中披露的端口与协议细节，是希望厂商能修补鉴权缺失问题，**不构成对任何人的攻击授权**。
> - 所有实验应在车辆静止、驻车状态下进行。作者不对任何误用或损坏承担责任。

## 结论先行

| 问题 | 结论 |
|---|---|
| 能把自定义画面投到仪表吗 | **能**。已实测 240×320 与 1920×720 全屏投放，画面正确、倒计时正常、到点自动还原 |
| 能保留原车仪表内容吗 | **能**，但靠的是硬编码几何遮罩（顶部 96px、底部 60px、左右 32px），与固件版本强耦合 |
| 能跑到 30 fps 吗 | **不能**。瓶颈在仪表侧 tinf/zlib 解压，实测 90–140 ms/帧，上限 5–8 fps |
| 需要 root 车机吗 | **不需要**。走仪表自己的管理端口，车机侧只是普通 App + TCP |
| 会占用仪表存储吗 | 只在 `/tmp`（tmpfs，64 MB）里放 ~6.4 MiB 程序 + 2.2 MiB DMA 缓冲，**断电即消失** |

## 链路

```
┌─────────────── 中控（au8295_xp / Android 12）───────────────┐
│                                                             │
│  ICLock.apk ──渲染──▶ 1920×720 RGB565 帧                    │
│       │                                                     │
│       │ ① TCP 连 172.20.1.40:30510（仪表管理 RPC，无鉴权）   │
│       │ ② 本机 ServerSocket:9971，让仪表回连拉取 armv7 二进制│
│       ▼                                                     │
└───────┼─────────────────────────────────────────────────────┘
        │ 车内网 eth0 172.20.1.x
        ▼
┌─────────────── 仪表（Linux 3.0.35 / armv7l / i.MX6, root）──┐
│  30510 ──▶ root shell ──▶ /tmp/iclock/bin                    │
│                              │                               │
│                              ├─ 采样 fb0（1920×720 32bpp）    │
│                              ├─ 四段渐变遮罩合成              │
│                              └─ 写 fb1（RGB565 前景叠加层）   │
└──────────────────────────────────────────────────────────────┘
```

关键点：仪表 `fb0` 是显示控制器扫描输出的**只读**帧缓冲，`fb1` 才是可写的前景叠加层。
所以做法是**每帧重新采样 fb0、按几何遮罩盖住中间区域、再写回 fb1**——
原车报警灯闪烁和指针扫动会自然透出来，不需要任何 IPC 或动画同步。

## 快速开始

```bash
# 0. 前置：adb 连上车机，车机能通仪表 172.20.1.40
export ADB=/path/to/adb

# 1. 零写入探查（不改任何仪表状态）
./car-probe.sh

# 2. 最小投放验证：显示 120 秒后自动还原
cd mini && ./deploy.sh

# 3. 完全脱离电脑：安装 APK，手机/车机上点一下即可
$ADB install -r android/ICLock.apk
```

`android/build.sh` 是**不依赖 Gradle / Android Studio** 的手工构建链
（aapt2 + D8 + apksig），需要自备 `aapt2` / `r8.jar` / `apksig.jar` / `android-all-12.jar`，
脚本里有下载地址提示。

## 实测环境

| 项 | 值 |
|---|---|
| 车机 | au8295_xp / E28U / Android 12 / uid 2000 (shell) |
| 仪表 | Linux 3.0.35 armv7l，i.MX6，`uid=0(root)` |
| 中控车内网 | `172.20.1.45`（eth0） |
| 仪表 | `172.20.1.40`，管理 RPC `30510`，帧口 `49173` |
| fb0 | 1920×720，32 bpp，只读 |
| fb1 | RGB565 叠加层；基线 240×320/16bpp/stride 480/virtual 240,960 |
| 寄存器 | `0x02740000` com=4，`0x02740004` gw=`0x80000000`，`0x02740008` pos=0 |
| `/tmp` | tmpfs 64 MB，rw，无 noexec |

## 已知限制

1. **几何遮罩写死**：`y<96`、`y≥660`、`x<32`、`x≥1888` 是按本车仪表版式量出来的，
   换车型或换固件版本必须重新量，否则会盖掉或露出错误区域。
2. **帧率天花板 5–8 fps**：仪表侧 zlib 解压在 90–140 ms/帧。想提帧只能换方案
   （LZ4、脏矩形、或改成数据驱动——只传指针/转速等数值，让仪表本地渲染）。
3. **依赖一个无鉴权端口**：30510 只要网络可达就返回 root shell。这是本方案成立的前提，
   也是它最大的安全隐患；厂商一旦加鉴权，整条链路立即失效。
4. **通道兼容性**：`/dev/...` 的 channel ioctl 在本车返回 `0x0a6ff7ff`（期望 `0x0a6ff7fe`），
   原厂 receiver 会据此判 `instrument_busy` 而拒绝启动——这是原方案在本车型上的硬伤。
5. **App 被回收后无法手动停止**：仪表侧程序独立倒计时，到点自动还原，期间只能等。
